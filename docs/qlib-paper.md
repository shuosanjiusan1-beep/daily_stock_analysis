# 独立 Qlib A股模拟辅助

新增 `.github/workflows/02-qlib-paper.yml`，不修改既有工作流。只做模拟研究，不连接券商、不提交真实订单。模型候选不构成实盘指令。日线无法提供实时盘中交易能力。

## 已验证的基线

使用 Microsoft Qlib v0.9.7 的 `examples/benchmarks/LightGBM/workflow_config_lightgbm_Alpha158.yaml`，保留原训练/验证/测试区间、模型参数、TopkDropoutStrategy 和费用参数，仅改变本地数据路径、模型线程数为2、数据进程数为2。配置与 Microsoft MIT 许可位于 `scripts/qlib_paper/`。

2026-11-25 本地实测：社区数据发布版本 2026-11-24，SHA-256 为 `f6d58ddb24841df5bb7c28b0bc2014e62939737c974747087ce5e8bec8aa1c38`；当日300只沪深300成分及指数的 OHLCV 全部有效。2017-01-03 至2020-07-31 共871个回测日，Qlib `risk_analysis` 的费用后策略年化指标约24.94%、最大回撤-26.63%；费用后超额年化指标约13.58%、超额最大回撤-8.29%。这是该社区数据和官方历史区间上的一次工程验证，不是官方成绩复现保证，也不是未来收益保证。社区历史数据可能修订，成分历史及复权质量尚未独立审计。默认年化口径由固定版本 Qlib 的 `risk_analysis` 定义。

## 启用

1. 进入 Actions → **Qlib A股独立模拟辅助** → Run workflow → `validate`。只有数据时效及完整官方回测通过后继续。
2. 运行 `commission`：重新验证、向既有收件人发测试邮件，然后创建 `qlib-paper-state` 分支内的 `paper-state.json`。重复初始化会拒绝，绝不会重置已有账本。首次需允许此工作流 `contents: write`，仅用于模拟状态；无需个人访问令牌。
3. 运行 `pre`，核对邮件与账本。初次只生成信号，不追溯虚构历史成交。
4. 仓库 Settings → Secrets and variables → Actions → Variables 新增 `QLIB_PAPER_ENABLED=true`，启用定时任务。停用设为 `false`。原有工作流不受影响。

复用已有 `EMAIL_SENDER`、`EMAIL_PASSWORD`、`EMAIL_RECEIVERS`、`GEMINI_API_KEY`、`TAVILY_API_KEYS`。前三项必需，密码由 GitHub 仅在发送步骤注入；不要打印环境或将密钥贴入日志/对话。Gmail 使用现有应用专用密码和 TLS。新闻为可选增强，使用 Tavily 第一把配置的密钥；Gemini 需要已有 `GEMINI_MODEL`（变量或 secret），未配置时只列新闻来源。服务失败会明确标记摘要不可用，不能改变模型信号和账本。未加载原项目的全量配置及通知模块，避免隔离依赖环境触发其他渠道或券商初始化。

本地使用：创建独立 Python 3.11 环境，安装 `scripts/qlib_paper/requirements.txt`，执行 `python scripts/qlib_paper/run.py validate`。macOS 的 LightGBM 还需要 OpenMP 运行库；GitHub Ubuntu runner 不需要该手动步骤。`--provider` 可指定已下载的 Qlib 数据目录；`--output` 指定报告目录。不要向本地复制 GitHub Secrets。

## 三时段和数据边界

- 盘前：北京时间08:20，要求上一交易日完整日线；结算上一日模拟交易并训练新信号。
- 盘中：11:10，只展示已结算账本和新闻，明确标注日线日期；不读取实时价、不做盘中成交。
- 盘后：19:30，要求当日日线；没有更新就发“数据未齐”状态，次日盘前重试。

GitHub cron 使用 UTC，可能延迟，不能当作精确定时交易服务。节假日使用 XSHG 日历过滤；日历超出覆盖范围时失败关闭。社区数据本次发布时间为北京时间次日01:10，所以盘后状态邮件是正常情况。每次下载校验发布清单中的 SHA-256 和大小，同时检查实际 OHLCV、成分覆盖与指数；发布日期不能代替时效。最多允许5%成分日线缺失，但实际持仓或目标有缺价/停牌时整次结算暂停。

## 模拟规则与持久化

当前信号使用与官方相同的 Alpha158/LightGBM，另用约三年训练、半年验证、两个交易日标签隔离的滚动窗口。这与官方历史基线不是同一收益测试。候选限定普通沪深主板代码；前5只用于模拟目标，最多5只持仓，新建仓每只最多当日资产16%，保留约20%现金，100股整手，禁止当日买入当日卖出。信号日之后的下一交易日开盘价加5个基点滑点用于模拟买入，卖出减5个基点；买入费率0.05%、卖出0.15%、最低5元均为保守模拟假设，不声称是现行实际券商费率。

日线到齐后才补记模拟成交。开盘相对前收盘涨跌幅绝对值≥4.5%时不假设成交；这只是保守跳空保护，不是完整ST、涨跌停、交易状态或盘口撮合引擎。停牌/缺价、持仓复权因子变化、跨过未处理交易日等会暂停并要求核查，避免错误拆股/分红记账。暂停不是自动修复：需要核对数据和账本后恢复，不能直接清空重建来隐藏问题。

状态仅含虚拟现金、虚拟持仓、信号、最多1000条模拟记录和120个邮件去重键，保存在独立 `qlib-paper-state` 分支。公开仓库的模拟状态也是公开的，不应填入真实持仓或身份信息。所有状态写入校验原文件SHA，并且工作流串行执行，冲突失败不得覆盖。账本保存后才发送邮件；SMTP成功与去重状态保存无法跨服务形成原子事务，极少数故障可能重复邮件，但同日结算不会重复交易。保存失败、密钥缺失、邮件失败使任务失败，不假装成功。数据包与模型文件不提交至仓库。

## 验证与恢复

运行 `python -m unittest discover -s tests -p test_qlib_paper.py -v`；`validate` 输出 freshness、benchmark JSON 和费用后每日回测CSV；每次邮件正文保存为 artifact，保留30天，不上传环境、密钥或原始API响应。邮件为纯文本，可通过 artifact 的 `report.txt` 审查。

发生问题先把 `QLIB_PAPER_ENABLED=false`，保留状态分支和运行记录，检查最后成功日期与当次 artifact。恢复旧状态时需审查对应 GitHub 提交及日期，禁止盲目重复初始化或删除分支。删除新增工作流即可撤销调度；已有9个工作流、API/Web/Desktop/Docker以及默认依赖不变。新英文说明未单独增加，因为这是此仓库用户特定的中文部署能力，不修改原有双语文档契约。
